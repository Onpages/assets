Кастинг-ассистент

1 Цель

Сервис в Telegram вокруг кастингов, который снимает с Коли (а потом с бригадиров и актёров) рутину: мониторинг кастингов, отсев, заявки, ответы на вопросы, занятость, память по контактам. Два контура:

  • КОНТУР А (v1) — личный ассистент на аккаунте Коли: читает кастинги, отсеивает, проверяет входящие, отправляет заявки, отвечает, следит за занятостью.
  • КОНТУР Б — система для бригадиров: каждый бригадир подключает свой аккаунт через QR, ведёт работу одной фразой, нейросеть формирует и рассылает кастинги, ведёт паспорта актёров и заявки.

2 Роли в системе

  • Коля — владелец; слово Коли = истина; аккаунты и номера регистрирует только он.
  • Кастинг-ассистент (новый чат) — «голова»: разметка, отсев, классификация, черновики, занятость, паспорта, формирование кастингов.
  • Чат «Секретарь» — «руки»: сбор как есть и отправка только по явной команде Коли. На старте контура А TG-действия делает Секретарь «в режиме Актер» под аккаунтом Коли.
  • Бригадир — размещает кастинги, подключает свой аккаунт (QR), помечает заявителей, закрывает кастинги.
  • Актёр — получает предложения, подаёт заявки, видит свой рабочий чат.
  • Помощник по всем проектам — протоколирует развитие функционала, в реализацию не лезет.

3 Контур А — функционал v1

Восемь функций Ф1–Ф8.

  • Ф1. Мониторинг кастингов: чаты/каналы бригадиров из TG-папки «Бригадиры» (папку создаёт Коля); новый кастинг-пост → карточка: источник, ссылка, текст, требования, даты, контакт. Сбор — по команде Коли или в рабочей сессии Секретаря; без фоновых процессов.
  • Ф2. Разбор и отсев: разметка по критериям Коли: «под критерии / вне критериев / непонятно»; до ввода критериев — показывать всё с разметкой (отсев не включать).
  • Ф3. Контроль входящих: непрочитанные из папок «Бригадиры»/«Актёры» → классификация (вопрос / ответ бригадира / приглашение на съёмку / отказ / иное) + пометка «требует ответа» + черновик ответа Коле по каждому.
  • Ф4. Заявки бригадирам: заявка = текст по шаблону Коли + фото + ссылки из TG «Избранного» (Saved Messages); собирает Секретарь; отправка ТОЛЬКО по явной команде Коли на каждую заявку; факт — в журнал и карточку контакта.
  • Ф5. Ответы на вопросы (актёрам и бригадирам): только разрешённое инструкциями Коли («что контакту можно знать»); чего нет в разрешённом → вопрос Коле, не выдумывать.
  • Ф6. Занятость: Коля диктует занятые даты/съёмки → календарь занятости; учитывается при разметке и в черновиках (на занятые даты не обещать).
  • Ф7. Память по контактам: карточка на каждого: канал, статус, проект, что он знает / о чём говорили, история переписки; статус, проект и правила «что можно знать» обозначает Коля. Незнакомец без карточки — осторожный режим: только черновик Коле, наружу ничего.
  • Ф8. Сводка Коле: одним сообщением — новые кастинги с разметкой, входящие без ответа, отправленные заявки, конфликты занятости.

Границы v1 (НЕ входит)

QR-доступ к аккаунтам бригадиров (вошло в контур Б отдельным словом Коли); автоотправка без явной команды; фоновый демон; проект «Модели» не трогаем (только разметка контактов); e-mail не в v1; ML-классификация не в v1 (отсев правилами/ключевыми словами).

Критерии готовности v1

Сводка с разметкой по команде; заявка уходит только по команде и фиксируется; входящие разобраны с черновиками; занятость учитывается; ни одного TG-действия вне штатных скриптов; инцидент → стоп и доклад.

4 Контур Б — бригадирский

4.1 Подключение

  • Каждый бригадир подключается через QR-код: помощник заходит в аккаунт бригадира.
  • База знаний для новичков — будет.
  • Можно подключить и существующий аккаунт, не заводя отдельный.

4.2 Паспорта

  • Паспорт актёра: параметры, навыки, район/место жительства, исключения по типам проектов («я не участвую в судебных шоу… медицинские шоу — тоже не хожу»), типажность (бандит, учёный; наполняет сам актёр + из переписки и утверждённых ролей), манера общения.
  • Паспорт бригадира: манера общения, выжимка переписки с актёром («с кем на "ты", обращение по имени»).
  • Паспорт пополняется из переписки автоматически: бригадир уточнил права категории «Б» — нейросеть запомнила; когда понадобится — «вывела всех с правами → выбрал, кому предложение в личку».
  • Надёжность актёра: личные и общие заметки бригадиров («опоздал», «много говорит»); больше плохих пометок — ненадёжнее. Источники: личные пометки бригадира + групповой чат бригадиров.
  • У бригадира может быть своё виденье типажа актёра — персональная пометка.
  • Первичная база при подключении существующего аккаунта: нейросеть перечитывает все переписки с актёрами и создаёт базу (навыки, кто где живёт).

4.3 Рабочие чаты

  • Личный рабочий чат бригадира: отчёты о работе, заявки, отметка выбранных.
  • Личный рабочий чат актёра.
  • Групповой чат бригадиров (создаст Коля): общение бригадиров, «скидывают накосячивших актёров», нейросеть читает, запоминает, обсуждает новые функции, отвечает на вопросы; участие по желанию — кто не состоит, общается в личном рабочем чате.
  • Групповой чат бригадира с актёрами: нейросеть отвечает в рамках сегодняшней смены, уточняет, если кто-то что-то забыл.

4.4 Жизненный цикл кастинга

  1. Бригадир ставит задачи одной фразой на несколько дней. Эталон Коли:

    «на завтра и послезавтра нужна девушка с собакой, на завтра 5 журналистов… машина такси и на послезавтра дублер по параметрам, а в ближайшее время — узбечка уборщица 20 лет, которая может подъехать в течение часа в Долгопрудный»

  2. Нейросеть помнит контекст проекта («исторический проект — добавляет: без татуировок на видимых местах»), уточняет возраст, гонорар, формирует кастинги.
  3. Черновик → правки бригадира → подтверждение рассылки («подтвержденные кастинги рассылаются»); не авто.
  4. Состав рассылки подтверждённого кастинга: публикация в группах от имени бригадира + адресные ЛС актёрам, в т.ч. по выборке паспортов: «Напиши всем лысым мужчинам, кто живет на Юге Москвы, кто может приехать в Бутово в течение часа».
  5. Заявки: результаты выводятся в рабочем чате бригадира, упорядочены по «близости к требованиям» и «надёжности».
  6. Утверждение — два пути: нейросеть делает всё после подтверждения бригадира; или бригадир сам пишет в личку, кого утвердил, — нейросеть читает, закрывает кастинг, неутверждённым пишет сама. Цепочка:

    «Нужных пометил → запросил подтверждение → подтверждение получил → кастинг закрыл»

  7. Закрытие: бригадир сообщает «кастинг закрыт» → всё опубликованное в группах удаляется; в рабочем чате остаётся; тем, кто подавал и не утверждён, — ЛС с отказом.
  8. Архивный чат кастингов — общий для системы, не чистится, для сверки данных.
  9. Самопробы: «картинка с текстом»; референс персонажа («схожесть по прическе») — бригадир прикрепляет картинку.
  10. Интерфейс: никаких своих кнопок — только нативные кнопки Telegram («отправить», «прикрепить файл»).
  11. Обучаемость: «чем больше люди общаются, тем нейросеть больше понимает… перенимает их манеру речи в личном общении».

4.5 Каналы

  • Яндекс.Диск (определённая папка), почта, MAX, WhatsApp — «где удобно там и работайте»; звонки и голосовые — пока НЕ делаем.
  • ТГ-действия для бригадиров: от их аккаунта, без массовых рассылок, с лимитами (числа лимитов подтвердит Коля; старт консервативно, пауза при FloodWait).

5 Паспорт кастинг-поста

Из реальных образцов 01.11.2026: канал @castingiKino, 50 постов + личная переписка с бригадирами, 104 диалога.

Поля для извлечения (что встречается в постах):

  • название проекта / жанр;
  • дата(ы) смены;
  • время сбора и место (метро / выход / как найти);
  • роли списком: название, возраст «38-45л», пол, рост «ОТ 170+», реплики/без, гонорар за смену «💰2000», ставка «1000», ориентировочное время окончания;
  • особые условия (без тату, своя собака, фотоаппарат и пр.);
  • требуемые данные от кандидата (фото, видеовизитка вложением, рост / размер одежды / обуви, ФИО / телефон, СЗ / ИП / гражданство);
  • контакты (wp / Max / телефон, TG-username, почта);
  • организатор («Создатель», имя).

Типы постов (различать!): (а) объявление — открытый кастинг; (б) ростер на смену — список уже утверждённых/кандидатов с пометками ✅; (в) служебные — «не утвердили», изменения времени/локации.

Форматы — зоопарк: от жёсткой структуры до свободного текста; разметка ведётся по полям, чего нет — «не указано», не выдумывать.

6 Безопасность, лимиты, персональные данные

  • Бан-риск TG: вход по QR — одна попытка; без фоновых процессов; без массовых рассылок; лимиты на публикации/ЛС (числа подтвердит Коля; старт консервативно, пауза при FloodWait, не более N публикаций/час).
  • Чужие сессии (аккаунты бригадиров): хранение — отдельный файл сессии на аккаунт, доступ только у системы; утечка = инцидент; ответственность — только по явному согласию бригадира.
  • Безопасность актёра:

    «актер не может распросить нейросеть про проект больше, чем ему нужно знать о проекте. Только в рамках съемочного дня (смены)»

  • Персональные данные 🚩4 · ждёт слова Коли: паспорта (район жительства, медицинские исключения), выжимки переписок, списки «накосячивших» — чувствительные данные. Предложение: хранение в приватном репо проекта; при онбординге актёра — короткое уведомление «что система хранит»; паспорта и пометки наружу не передавать; «накосячивших» — только внутри системы бригадиров.
  • Незнакомцы: осторожный режим (только черновик Коле). Аккаунты и номера регистрирует только Коля.

7 Этапы реализации

  • Этап 1 — Контур А (v1) на аккаунте Коли: Ф1–Ф8 силами связки «Секретарь (руки) + Кастинг-ассистент (голова)»; данные v1 (карточки кастингов, журнал заявок, календарь занятости, база ответов) — в репо проекта; критерии готовности из раздела 3.
  • Этап 2 — каркас Контура Б: QR-подключение бригадира №1, паспорта (первичная база по его перепискам), личные рабочие чаты, жизненный цикл кастинга на одном бригадире.
  • Этап 3 — масштаб: групповой чат бригадиров, поиск по параметрам + адресные рассылки, каналы (Диск / почта / MAX / WhatsApp), архивный чат, база знаний новичков.

8 Ждёт слова Коли

Эти пункты блокеров ТЗ не дают, но нужны до соответствующих этапов.

  1. Критерии отсева кастингов (Ф2) — Коля опишет.
  2. Текст-шаблон заявки бригадиру (Ф4) — даст Коля.
  3. База «что можно говорить актёрам и бригадирам» / «что контакту можно знать» (Ф5) — пропишет Коля.
  4. Персональные данные и согласия (раздел 6) — режим доступа и уведомление актёрам.
  5. Числовые лимиты TG-активности (раздел 6).
  6. Этапность (раздел 7) — подтвердить или переставить.

Именно здесь комментарий бригадира полезнее всего: шаблон заявки (п. 2), ответы на вопросы (п. 3) и этапность (п. 6) напрямую зависят от того, как бригадиры привыкли работать.
